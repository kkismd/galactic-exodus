# Issue / PR / Review ワークフロー

このドキュメントは、Galactic ExodusプロジェクトにおけるIssue、PR、レビュー、クローズコメントのテンプレートおよびワークフローを定義します。

## 作成先
`docs/contributing/issue_pr_review_workflow.md`

---

## 1. Issue テンプレート

### 1.1 実装issue
```markdown
## 目的
## 背景
## 現在の挙動
## 目標の挙動
## 実装方針
## 変更対象
## 変更しない範囲
## 仕様反映先
## テスト方針
## 受け入れ条件
## 関連issue・PR
## 互換性および回帰点
## 未決定事項
```

### 1.2 判断issue
```markdown
## 目的
## 背景
## 評価項目
## 選択肢
## 比較基準
## 調査結果
## 結論・提言
## 影響範囲
## 実装負荷見積もり
## 関連issue・PR
```

### 1.3 棚卸し / 調査issue
```markdown
## 目的
## 背景
## 調査範囲
## 調査方法
## 発見事項
## 課題・リスク
## 推奨アクション
## 次のステップ
## 関連issue・PR
```

## 2. PR テンプレート
```markdown
Closes #xxxx
## 概要
## 判断 / 挙動
## 仕様反映
## テスト
## 対象外の確認
## 後続対応
```

---

## 3. PRレビューチェックリスト
```markdown
- [ ] Issueの目的と実装内容が一致しているか
- [ ] 変更範囲が適切かつ最小限か
- [ ] 仕様書（SRS等）への反映が正確か
- [ ] テストが適切に追加・更新されているか
- [ ] 既存機能への回帰がないか
- [ ] パフォーマンスへの影響は評価済みか
- [ ] コードスタイルがプロジェクトガイドラインに従っているか
- [ ] ドキュメントの更新が必要か
- [ ] AI貢献開示が含まれているか
- [ ] CLA/DCOトラilerは含まれていないか（アカウント所有者のみ署名可能）
```

---

## 4. Close comment テンプレート
```markdown
## 解決概要
[Issueの目的・目標に対する達成度を簡潔に説明]

## 実装サマリー
[主な変更点・実装アプローチを簡潔に説明]

## テスト結果
[テストの実施状況と結果を説明]

## 今後の課題
[残課題や改善点があれば記載、なければ「なし」と記載]

Closes #XXXX
```

## 5. ADR-liteとして背景・選択肢・決定・影響を取り込む方針
重要なアーキテクチャ判断については、以下の項目をIssueまたはPRに含めること：

### 背景
- なぜこの変更が必要か
- 現在の課題や制約

### 選択肢
- 検討された代替案（少なくとも2つ以上）
- 各案のメリット・デメリット

### 決定
- 採用された選択肢とその理由
- コンセンサス形成プロセス

### 影響
- 既存コードへの影響範囲
- パフォーマンスへの影響
- 互換性への影響
- 今後のメンテナンスへの影響

## 6. ワークフロー運用ルール
- **ベースブランチ**: `main`
- **運用ルール**: 1 issue - 1 PR
- **旧TBXパス**: `experiments/galactic_exodus/docs/contributing/...` は使用しない
- **統合ブランチ**: integrationブランチを現行手順として記載しない
